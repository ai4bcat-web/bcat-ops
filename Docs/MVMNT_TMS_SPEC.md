## 1. What MVMNT is

A cloud TMS for freight brokers (MVMNT, Inc.). One load record is the system of record:
every status change, document and financial entry hangs off it. Natively integrated with
DAT (load posting), Parade (capacity), Trucker Tools (tracking + document capture),
Highway (carrier identity / insurance / risk), HaulPay (factoring), QuickBooks Online
(invoices, bills, payees). `[PUBLIC]`

Public REST API `https://api.mvmnt.io/v1`, OAuth 2.0 client-credentials bearer token;
documentation at https://docs.mvmnt.io is behind a Redocly login. `[PUBLIC]`

## 2. Data model — Loads API `[PUBLIC]`

Endpoints: `POST /loads/filter`, `POST /loads`, `GET|PATCH|DELETE /loads/{id}`,
`POST /loads/{id}/add-carrier`, `POST /loads/{id}/rebook` (rebook after a TONU),
`GET|PATCH /loads/{loadId}/carriers/{carrierId}`, `POST …/carriers/{carrierId}/bounce`,
`POST …/carriers/{carrierId}/tonu`.

Schemas (property counts only are public — the field lists are a `[WALKTHROUGH]` item):
`Load` (13 props, 3 required) · `LoadStop` (8) · `Address` (12, 8 required) ·
`LoadCarrier` (15) · `LoadCarrierCharge` (5) · `CarrierReference` (8, 4 required) ·
`LoadFilter` (9) · `LoadStatusFilter` · `DatetimeFilter` · `UUIDFilter` · `PaginationInfo`
· `ReportTonuRequest` · `BounceCarrierRequest` · `RebookLoadResponse` · `AddCarrierResponse`.

Enumerations:

| Enum | Values known |
|---|---|
| `LoadStatus` | pre-transit: `SOURCING`, `BOOKED`, `DISPATCHED`; in-transit: `LOADING`, … (rest truncated — walkthrough); terminal: `DELIVERED` (+ likely `CANCELLED`/`TONU`) |
| `LoadBillingStatus` (carrier AP) | `AWAITINGINVOICE`, `INVOICEINREVIEW`, `APPROVEDTOPAY`, … |
| `LoadCarrierStatus` | `ACTIVE`, `TONU`, `BOUNCED` |
| `LoadCarrierRemovalReason` | (values not public) |
| `TransportMode` | `TL`, `LTL`, `AIR`, `OCEAN`, `RAIL`, `INTERMODAL` |

Tracking-driven operational statuses seen in the wiki (Trucker Tools event → MVMNT
status): Arrived at Origin → **Onsite Pickup**, Departed Origin → **Enroute**, Arrived at
Stop → **Arrived**, Arrived at Destination → **Onsite Delivery**, Departed Destination →
**Delivered**. Each event also writes a **check call**.

Design implication: a load carries **two independent status axes** — operational
(`LoadStatus`) and carrier-billing (`LoadBillingStatus`) — plus a per-carrier assignment
status, because a load can have more than one carrier over its life (bounce → rebook).
`TMS_DESIGN.md §4.5` has a single `status`; this needs the AP axis and the carrier
assignment history added.

## 3. Workflows `[PUBLIC]`, screens `[WALKTHROUGH]`

### 3.1 Shipper (customer) profile
- Statuses: Onboarding Sent → Onboarding Signed → **Customer** (only Customer can have loads built).
- **Credit limit** (default $50,000): available = limit − unbilled/unpaid loads; load creation is blocked when the shipper rate exceeds available credit. Paid invoices restore it. Admin-only edit.
- **Invoice settings**: required document types before invoicing (BOL, POD, rate confirmation, weight ticket, lumper receipt, temperature log, inspection report), required reference numbers (PO, PRO, delivery #, …) enforced at load build and at invoicing, invoice frequency / batch schedule (daily, twice-weekly, weekly), factor flag (remit-to switches between the factor and own bank).
- Profile defaults copied onto new loads: sales rep, GP split, billing requirements, saved facilities.
- Shipper visibility preferences: milestone emails, shared tracking link, shipper portal.
- Maps to BCAT: `Customer` already has `creditLimitCents`, `creditHoldFlag`, `paymentTermsDays`, `requiredDocsForInvoice`, `factored`, `defaultSalesRepId` (Phase 1). Missing: onboarding status ladder, required reference numbers, invoice frequency, visibility prefs, GP split, credit-available computation and the two gates.

### 3.2 Load creation
- Gate: shipper is Customer **and** available credit ≥ shipper rate.
- Fields: shipper, shipper rate + rate type (flat / per mile / per unit) + accessorials; origin/destination facility (name, address, city, state, zip, contact name + phone); pickup/delivery date-time or appointment window; equipment type (dry van, reefer, flatbed, step deck, …); commodity; weight; temperature target + range (reefer); special instructions; shipper PO + reference numbers (enforced per shipper config); auto-generated internal load number; owner / sales rep / GP split from the profile.
- Maps to BCAT: `Load` + `Stop[]` cover facility/appt; missing equipment type, commodity, weight, temperature, rate type, required-reference enforcement, credit gate.

### 3.3 Carrier assignment
- Carrier sourcing: MVMNT freight matching (lane + equipment + pickup date vs the carrier network), DAT posting from inside the load, Parade suggestions, Trucker Tools responses, direct outreach.
- Gate (automated): carrier status **Active**, cargo + liability insurance current (Highway), Highway risk not Unacceptable; Conditional needs documented manager approval.
- Fields on the load: carrier (from Active profiles), carrier rate, dispatcher name/phone/email (from profile), driver name + phone, **Quick Pay** flag with discount tiers (21 d 1.5 %, 15 d 2 %, 7 d 2.5 %, 1 d 3 %), real-time **gross profit** = shipper rate − carrier rate − other costs.
- Carrier rate confirmation sent for e-signature; shipper rate confirmation when the shipper requires one.
- Maps to BCAT: `Carrier` model is designed (`TMS_DESIGN §4.4`) but not built; own fleet (Ivan Cartage) is the "carrier" on most loads today. Need: carrier directory with insurance dates + status + risk, assignment gate, quick-pay terms, GP box, generated carrier rate con with e-sign (BlueInk is already integrated for HR docs — reuse).

### 3.4 Dispatch, tracking, in-transit
- Pre-dispatch checklist: load complete, carrier assigned at agreed rate, signed carrier RC on file, signed shipper RC if required, driver name + phone entered.
- Tracking priority: Trucker Tools (GPS, auto status + check calls + document capture) → **EZ Tracking** (MVMNT native SMS link, one GPS ping per tap) → manual check calls. A load must not move without one active method.
- Exceptions recorded on the load immediately with an operational record (what/when/facility/driver statement) and a financial record (amount, side shipper/carrier/both, accessorial type, new totals): detention, layover, TONU, rate adjustment, cargo claim. Planned: an "open exception" flag that blocks invoicing.
- Maps to BCAT: own trucks already stream Motive positions (`TruckLocation`) and the driver app reports stops; missing: carrier-side tracking link (the `LINK` provider in `TMS_DESIGN` Phase 8 is exactly EZ Tracking), check-call log, exception/accessorial entry with sides, status automation from geofence events.

### 3.5 Delivery and documents
- Delivered set automatically (Departed Destination geofence) or manually.
- On Delivered: carrier rating prompt (1–5 stars, feeds future matching), automated POD / carrier-invoice request email with an upload-portal link (carrier or its factoring company), shipper delivery notification per preference.
- Documents land on the load's document section (public/private) from Trucker Tools, the upload portal, or staff upload.
- Maps to BCAT: PODs page + driver-app PDFs already exist for own fleet; missing: carrier upload portal (token link, like the dispute portal), carrier rating, per-shipper notifications.

### 3.6 Invoicing & factoring
- Completeness check against the shipper's required docs + references → **invoicing queue** → batch invoicing per shipper schedule → invoice records sync to QuickBooks Online → **Send to Factor** (one click on delivered loads; auto-send optional) to HaulPay, or direct to shipper for self-financed accounts (remit-to switches automatically on the factor flag).
- Carrier invoice audit (six checks; Clean / Minor / Material) drives `LoadBillingStatus`: awaiting invoice → invoice in review → approved to pay → (paid).
- Stages visible to accounting: awaiting invoicing, invoiced, submitted, paid.
- Maps to BCAT: factoring queue + OTR integration already handle "send to factor" for own-fleet loads. Missing: shipper invoice records (Phase 4 of `TMS_DESIGN`), per-shipper batch cadence, carrier AP audit states, QuickBooks export.

### 3.7 Cash application, carrier payment, reporting
- Factor remittance receipt, short-pay investigation, chargebacks, reserve reconciliation (Phase 5 of the wiki); carrier payment + discrepancy handling (Phase 6); weekly cadence and month-end close reports (Phase 7).
- Maps to BCAT: Cash check-in page covers part of this for own fleet; carrier AP and factor reserve reconciliation are new.

## 6. Live findings `[WALKTHROUGH]` — 2026-10-27, Ryne's account

**App:** SvelteKit front end at tms.mvmnt.io; all data through a PostGraphile-style GraphQL
gateway (`gateway.tms.mvmnt.io/graphql`, Cognito JWT) — 10,975 types, 328 entity (table)
types, 336 domain enums. Nav: Dashboard, Shipments, Rates (`/quoting/shipper-quotes`),
Invoicing (`/accounts-receivable`), Carriers, Factors (`/carrier-factors`), Customers
(`/customer-management/customers`), Locations, Vendors, Workflows, Academy, My Brokerage
(`/brokerage/settings`). Ryne's org has no shipments/customers yet, so screens were read
from forms, the help center and the schema, not from data.

**Shipments board:** status tabs Today's Open / Booked / Load / Disp / Unload / In Transit /
Del; saved Views; filters Customer, Status, Pick Up on, Delivery on, Origin, Destination, AR
Status (default excludes Unbilled/Unpaid/Paid/Canceled = hides finished work); columns
Shipment ID, Status, Reference, Origin, Destination, Pick Up, Delivery, Stops, Customer Rep,
Customer, Carrier (+ "13 fields" picker); create = pick customer first (or add new).

**Tender workflow (help article):** Tender Pending → Accept (creates the initial *load*,
assigns the acting user as carrier rep; does not book a carrier) / Reject with reason enum /
Reset; acceptance can be blocked by credit (no limit, limit reached, invoice past max days
late); EDI 990 is sent on accept.

### 6.2 Data model (from the live GraphQL schema; scalars only, relations in prose)

Status columns on Shipment / Order / Load / LoadCarrier / VendedService / Appointment /
LoadCheckCall / CarrierProfile / ShipperProfile are plain strings (app-level enums, see the

(human number), `key`, `createdAt/updatedAt`, soft delete (`deletedAt/deletedById`),
`imported`, and `previousStatus` + `statusChangedAt` where there is a status.

### 6.4 Workflows from the help library — shipments (condensed)

- **Three records.** Order = sell side (customer, customer rep, mode, references, customer charges, order docs, AR state). Shipment = the operational movement (one status, linked orders + loads, tracking, detail page). Load = buy side (carrier assignment, carrier rep, load status, equipment, stops, carrier costs, load docs, AP state). Vended services (lumper, drayage vendor…) sit on the shipment without being a load. A consolidated shipment links several orders; a shipment can hold several loads. Statuses are per record: shipment DELIVERED does not imply invoiced, paid, carrier bill received, or carrier paid.
- **Create → Draft.** Shipments → "+ Shipment" → pick an *Active* customer (Pending/Blocked refused; credit-limit-required orgs need a limit first; optional "Add new customer" inline, hidden when customer approval or a credit limit is required) → draft editor. Mode defaults from the customer's default mode else FTL. Sections by mode: General (mode, customer contact), Stops (Transit for LTL/air/ocean; LTL = 2 stops Shipper/Consignee), Shipment Contents (freight/packages: handling unit, qty, dims, weight, class/NMFC, hazmat UN/subclass/emergency contact, stackable, high value), Financials (customer charges, Bill To, Cost Center), References, Notes, Equipment + Driver (truckload family), Containers (drayage/ocean), rate panels (LTL Rates, 7L air/ground quotes), Import/Export + Incoterms (international). Auto-saves on blur + "Save draft"; validation: stops chronological, weight units agree, hazmat fields, customer-required references, mode-required rates/carrier/equipment.
- **Submit.** "Submit order" re-saves, runs the credit check (limit present, available ≥ charges, no invoice past max days late). Truckload offers: Submit · Submit and assign to a carrier rep · Submit and book carrier (opens carrier selection for the first load). Draft stays editable only while the order is Draft.
- **Modes.** FTL, PTL, Bulk, Drayage, Intermodal, RLTL = truckload family (Equipment + Driver, stops, carrier/tracking/status actions). LTL = two-terminal rate flow (SMC3). Domestic Air / Express Ground = 7L quotes. International Air (MAWB/HAWB), Ocean (containers, pickup/linehaul/delivery legs), Rail, Auto (auto-broker orgs).
- **Locations & stops.** Location = reusable address (verified address, coordinates, time zone, Location ID reference, APPT vs FCFS, customer/external notes, carrier notes, contacts, special services, operating hours); scope Public (all customers) or per customer; "Used n times" + warning when editing a shared location. Stop = one use of a location with requested window (date, time from/to), APPT flag when confirmed; Additional Stop (Pick-Up / Delivery), Remove, mileage recalculated. On an active shipment each stop card offers: Schedule / Change appointment (who asked: Customer / Carrier / Broker + notes), Change requested date/time, Add In/Out times (TIME at stop; may advance the shipment status, e.g. first pickup in+out on a Dispatched shipment → In Transit), change location, edit references/notes, Swap with neighbour, Delete (never below one pickup + one delivery), change an intermediate stop's type.
- **Board.** Server-side search + filters (status, dates, customer, carrier, location, AR status…), column picker, sort, saved views (personal default, pinned, shared, AI-generated), CSV export of the current view (role-gated), single click = drawer (Summary, Details, Tracking, Documents, Financials, AI Agent), double click = full page, Order history tab inside a customer profile.
- **Tenders.** Email Tender Agent inbox → Tender Pending shipments (no draft, no load) → Accept (creates the initial load, assigns acting user as carrier rep; credit-gated; EDI 990) / Reject (reason) / Reset. Customer "Auto Accept" setting can accept automatically after the credit check.
- **Duplicate.** From a row or More options: up to 20 copies with pickup/delivery dates per copy, "Copy additional services", "Book the same carrier" (truckload, non-draft) — copies customer, stops, charges, reference definitions (blank values), equipment/special requirements, freight; credit check on total exposure.
- **Consolidate.** Select ≥2 Planning/On Hold shipments (compatible modes: PTL/FTL/RLTL/Bulk mix; air/ocean share linehaul only) → rule evaluation (status, equipment, freight, route, timing, capacity, appointments, cargo value, commodity, dedicated policy; BLOCK/WARN per category) → parent shipment with merged stops; each order keeps its customer/references; carrier cost allocated across orders. Unconsolidate only while Planning/On Hold with no carrier.
- **Cancel / delete / restore / revert.** Cancel keeps the record (blocked by a customer invoice; cancel booked loads separately or risk TONU); Un-cancel restores previous statuses (Planning / Sourcing when no carrier). Delete only Draft / Canceled / Tender Rejected; admin "Restore deleted shipment…" by exact ID. Revert to quote for single-order pre-booking shipments. Org claim can make cancel/delete admin-only.

### 6.5 Workflows — carriers, dispatch, tracking, documents, AP/AR (condensed)

- **Book carrier** (load in Sourcing, truckload, no active carrier): pick carrier (only "Allowed carrier statuses": Pending/Review/Active, or narrower) + carrier rep → review buy-side charges (no negatives) → contacts/drivers, booked equipment, tracking choice, dispatch details → compliance / insurance / spend warnings → Book. Preflight re-checks customer-required fields ("Review shipment" / "Continue anyway" for authorized users), double-booking guard. Warnings that block non-admins: *Carrier cost exceeds top spend* (fix Top spend on Financials), *Cargo value exceeds carrier insurance* / *could not be verified*. Success → load Booked → "Generate Rate Con and e-sign link" (expiry default 48 h; deliver by email, copy packet link, or Highway; optional Secure Rate Con delivery); carrier signs with required fields (driver name/phone/email, truck/trailer, plate, VIN, pickup ETA…) → RATE_CON_SIGNED event; org option "require signed rate con for dispatch" / "dispatch on rate con signed".
- **Dispatch** (load Booked + active carrier): dialog = event type Dispatch, rate-con warning, dispatch time, pickup ETA, tracking details (driver phone, dispatch email, truck, trailer, provider), note, next check call (date/time/note or "I don't need to schedule"). Load → Dispatched; shipment → Dispatched only when all loads are.
- **Tracking tab** per load: provider sessions (Trucker Tools, MacroPoint, Highway, Load Market; start/restart from the carrier menu), map, manual check calls. *Log check call*: date/time, Event type (dispatch, location update, arrival, departure, delivery, incident types…), status-change notice, location + notes, optional "send notes to driver via app", next check call scheduling; banner to edit the reminder. ETAs: *Edit booked equipment* → pickup ETA; linehaul delivery ETA inline. Public **Customer Link** tracking page (brokerage domain; contact = team or customer rep), emailable; LTL uses *Log tracking*.
- **Bounce carrier** (reasons: carrier can no longer take / gave it back / rejected rate con / other, notes ≤250) → assignment ends, load back to Sourcing, history kept. **Report TONU** (cause: customer not ready / consignee not ready / forgot to bounce / other; optional replacement load with new pickup/delivery dates that also update the order) → assignment marked TONU, existing carrier costs stay payable (Awaiting invoice / In review / To be paid).
- **Sourcing tab**: lane search across Load History, Truck Postings, Greenscreens, DAT, MacroPoint History, Trucker Tools, Truckstop → select carriers → *Request quote(s)* (email, optional Book-now rate) → buy-side offers table (Requested, Quoted, Received reply/counter, Sent reply/counter, Won, Lost, Canceled) with Accept (books + rejects the rest), Counter, Reject (reason), Copy link; *Log carrier offer* for phone quotes; cross-shipment *Carrier Offers* page.
- **Load boards**: Post load (DAT, Truckstop, Loadboard Network, Convoy, FreightLink) with price, commodity, cargo value, equipment, length, weight, partial, requirements, lane, dates, notes (DAT shows 70 chars); postal-code aliases; per-listing Edit / Refresh / Remove / Repost with Active / Expired / Inactive badges.
- **Documents tab**: sections per customer order (EXTERNAL), per load carrier (INTERNAL), per vended service; upload with document type; *Send docs* → generate BOL (and others) → Email Document (from/to/cc/bcc suggested from customer contacts, preview); generated files are saved, not rewritten; required-document checks read customer or org requirements; deletion can be admin-only.
- **AR readiness**: delivered order = *Docs needed* → *Ready to invoice* checks required documents (customer + active carrier scope) and references and warns on a $0 sell total (*Invoice not needed* closes AR instead) → *Unbilled* (ready @ time) → *Generate invoice* → *Unpaid* → *Paid*; *Not ready to invoice* undoes; admin override when requirements are missing; early release before delivery possible.
- **AP ladder** per carrier/vendor bill: *Awaiting invoice* → *Record bill* → *In review* (optional stage) → *Approve to pay* → *To be paid* → *Record carrier / carrier-factor / vendor payment* → *Paid*. Payment groups (AP by payee, AR by customer) hold allocations to invoices; credits (AP/AR) apply at payment time; factor-managed bills show the factor link instead.

- **Vendors**: vendor profiles (status, docs W-9/COI/authority, contacts, locations, payment methods, service types) → *vended services* on a shipment with their own costs, documents and AP ladder.

### 6.8 Status vocabularies (verbatim from MVMNT's glossary)

- **Shipment status** (board short label in brackets): Draft [DRAFT] · Tender Pending [TEND PNDG] · Tender Rejected [TEND REJ] · Open [OPEN] ready to book · On Hold [HOLD] · Booked [BKD] · Planned [PLND] (LTL/forwarding) · Dispatched [DISP] · Loading [LDG] arrived at pickup · Picked Up [PKD UP] · In Transit [INTRAN] · Recovered [RECVRD] (forwarding) · Arrived At Delivery Terminal [ARVD @ DEL] · OFD [OFD] · Unloading [UNL] arrived at drop-off · Delivered [DEL] (TONU shown when every carrier was a TONU) · Canceled [CXLD]. Truckload family uses Booked → Loading → Unloading; LTL/forwarding uses Planned → Picked Up → Recovered → OFD. In/out times at stops drive Loading / In Transit / Unloading / Delivered.
- **Load status**: the shipment movement labels plus two of its own — *Sourcing* (needs a carrier; booking → Booked, or Planned for LTL/forwarding; bounce → back to Sourcing) and *Invoicing* (delivered, carrier invoice in review; only with the AP In Review setting). Carrier assignment outcomes: ACTIVE, BOUNCED (reason kept in Carrier history), TONU.
- **AR status** (per customer order, after delivery): Docs needed [DOCS] → Unbilled [UNBILLED] (ready to invoice; optional stage) → Unpaid [UNPAID] (invoice generated) → Paid [PAID]. $0 order → Paid via *Invoice not needed*; *Invoice early* can show Unpaid/Paid before delivery.
- **AP status** (per carrier load and per additional service): Awaiting invoice [WAIT INVC] → In review [IN REVIEW] (optional) → To be paid [TO BE PAID] → Paid [PAID].
- **Customer status**: lead stages New · Contacted · Qualified · Quoted · Nurturing; Pending (needs admin approval) · Active · Dormant (no order for 90 days, automatic, reverts on a new order) · Closed (lead) · Blocked (deactivated). Board tabs: Leads / Active / Inactive.
- **Carrier status**: Pending (until the carrier agreement is signed; non-TL types start Active) · Review (signed, approval required) · Active · Inactive (reason) · Do Not Use (reason). Booking allowed per org setting: Active only / Active + Review / Active + Review + Pending.
- **Quote status** (customer, sell side): Draft/Created · Requested · Quoted · Rcvd reply / Rcvd counter · Sent reply / Sent counter · Won · Lost (reason, incl. Expired) · Broker pass · Canceled · Not a quote. Accepting one quote on an email thread closes its siblings (priced → Lost, unpriced → Canceled). **Carrier offers** (buy side) reuse them: Requested, Quoted, Booked (= Won), Not booked (= Lost), Carrier pass / Broker pass, Canceled.
- **Additional (vended) service**: Active → Delivered → (Canceled), each with its own AP status.
- **EDI**: 204 inbound tender → Tender Pending; 990 outbound response; 214 outbound status; 210 outbound invoice; 997 acknowledgment status on the EDI log.
- **Money vocabulary**: Linehaul + Fuel surcharge = Customer Rate / Carrier Rate (sell / buy rate, accessorials excluded); Revenue / Cost = totals incl. accessorials; Margin = (Revenue − Cost) ÷ Revenue; Top spend = max carrier cost allowed on a load (booking warning above it); Target buy; Book-now rate (carrier self-booking).
