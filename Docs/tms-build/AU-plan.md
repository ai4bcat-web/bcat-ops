## 1. Decisions

- **D1 No schema, no new model/GSI/resource.** Everything rides existing `ShipmentDocument` (`stopId`, `loadCarrierId`, `audience`, `version`, `supersedesId` already exist), existing Lambdas, existing enums (`ShipmentMessage.kind` `'OTHER'`). Amplify template stays at 963,479 B, resources at 460/500. One Lambda action added to an existing function; no IAM/env changes. Needs only the shared deploy, no data deploy (confirm in AT2: do not add enum values).
- **D2 Move the BOL model out of `documentData.ts` into `src/lib/bolModel.ts`** (pure, relative imports only, Lambda-safe like `documentData.ts`). `documentData.ts` keeps the load summary. Clean cutover: `bolData`, `BolInput`, `BolParty`, `BolCarrier`, `BolOptions`, `DEFAULT_BOL_TERMS`, `BolReference` move; update importers (`GeneratedDocumentDialog`, `bolPdf`, `documentData.test` BOL block → `bolModel.test.ts`).
- **D3 The "no money" invariant stays by construction.** `BolInput` gains no rate field. "Include rates = Yes" is a separate optional `BolRates` member that only the builder's `includeRates` branch can fill, from **customer-side** charges only (`bundle.charges` where `side === 'CUSTOMER'`; never `CARRIER`, margin, or financials). A rated BOL is stored with **audience `CUSTOMER`** (not Public/ALL), which the existing `canEmailTo`, `EMAIL_DOCUMENTS` and the thread's "for the customer only" check already keep away from carriers/drivers. Default is No (spec), and the dialog states the consequence in one line. The existing test "no key matches cent|margin|rate…" is kept for the default build and a twin asserts the rated build contains no `CARRIER` charge and no profit/cost key.
- **D4 Slot-aware versioning.** `nextVersion`/`supersede` key on `(type, loadId)` today. Add optional `stopId`, `loadCarrierId`, `rated` to the key (undefined = null = today's behavior, so every existing caller and the RATE_CON/LOAD_SUMMARY paths are unchanged): master BOL slot = `(BOL, loadId=null, stop=null, carrier=null, plain)`; per-delivery-stop BOL = same with `stopId`; per-carrier BOL (multi-carrier) = with `loadCarrierId`; a rated BOL is its own slot so generating a rated copy never supersedes the driver's copy. `saveGeneratedDocument` passes the same fields to `assertPlacement`/row (`stopId` is already a column). This function is shared with the multi-carrier RATE_CON-per-carrier change → **single owner: AT2 lands the signature, MC uses `loadCarrierId` through it** (see §6).
- **D5 BOL is allowed on a DRAFT shipment** (the state right after "Create shipment"), still refused for CANCELED/voided. `saveGeneratedDocument` guard becomes: `type !== 'BOL' && status in (DRAFT, CANCELED)` refuses; `BOL && CANCELED` refuses. RATE_CON/LOAD_SUMMARY on DRAFT stay refused. Without this the spec's "after Create" row is dead on arrival. (Open for Ryne in §8: confirm a BOL may exist before Submit order.)
- **D6 Build from the saved bundle, not live form values.** The Generate row is disabled while `form.dirty` ("Save changes first — the BOL prints what is saved"), so the PDF can never disagree with the stored shipment. Needs `dirty` on `FormCtx` (`sectionProps.ts`, one field; `ShipmentFormPage` passes `form.dirty`).
- **D7 One shared letterhead.** Extract `drawHeader`+`resolveLogo` from `carrierRateCon.ts` into `src/lib/pdfLetterhead.ts` (`resolveLetterhead(doc, division, loadLogo)`, `drawLetterhead(doc, {legalName, ids, address, phone, title, subtitle, logo})`); `carrierRateCon.ts` and `bolPdf.ts` both call it. Same white plate, 150×38 box, alias `division-logo`, text fallback; BOL adds an address/phone line (band stays 70 pt). The existing `carrierRateCon.test.ts` logo tests are the regression net; the rate con PDF must be byte-for-byte equivalent in layout. Legal name source `Division.legalName || name`; address `physicalAddress` then `remitToAddress`; phone `Division.phone` then `settings.trackingContact.phone` (today the BOL only uses the latter).
- **D8 References on a BOL = all references that may leave the building**: order-level + stop-level refs with visibility `CUSTOMER` or `ALL` (existing rule, kept); `INTERNAL` never; `CARRIER`-only refs stay off (a BOL has audience ALL and can reach the customer). The PO prints first ("Customer ref (PO)"). "All References" in the spec is read as "all shareable ones" — flag to Ryne.
- **D9 E-mail goes through one new Lambda action `EMAIL_BOL`** in tms-shipment-actions (new file `bolEmail.ts`, one `case` + union entry in `handler.ts`), modeled on `sendRateCon`, not through `SEND_SHIPMENT_MESSAGE`. Why: the thread path is single-recipient, unvalidated (header injection via `to`), cannot open the thread, and refuses CUSTOMER docs; fixing it touches the tracking agent's hot path. `EMAIL_BOL({documentId, to[], cc[], message?, party})`: validate each address with `isEmailAddress` (≤20), doc must be `type BOL`, `ACTIVE`, `audience ALL` (a rated BOL → refuse with "customer copy: send from Documents → E-mail"), same shipment; `composeRateConCc` (tracking mailbox + sender, deduped); open the thread like `sendRateCon` if `threadKey` missing; raw MIME with the PDF read from S3 (never from the browser — the stored, versioned bytes are what is sent); write a `ShipmentMessage` (`kind 'OTHER'`, `party` from input ∈ CARRIER/DISPATCHER/DRIVER/CUSTOMER, `documentIds:[id]`, `attachments` meta, `[ref]` subject token, SES id → `providerRef`, wire `messageId`) so replies thread and it shows in the shipment thread/Tracking view; audit `EMAIL_BOL {documentId, to, cc, emailStatus}`; SES-denied dev → `NOT_SENT` + presigned download in the answer (same contract as `EMAIL_DOCUMENTS`). The send helper (`sendRateConEmail`) is generalised to take N attachments (rename `sendThreadMime`), rate-con call site adjusted — AT2 owns that edit in `handler.ts`.
- **D10 Recipient picker** reuses `RecipientPicker` + `knownRecipientOptions`/`parseCcList`/`dedupeEmails` from the rate-con batch (`features/carriers/components/`). Options for a BOL: pickup/delivery stop contacts (`documentContact.email`, `contact.email`, `Location.apptContactEmail`, labelled "Shipper contact"/"Consignee contact"), each active carrier's dispatcher (`LoadCarrier.dispatcherEmail`) and driver e-mails (`form.carrier.driverEmail1/2`), plus typed extras. **Nothing is preselected** (a BOL e-mail is a deliberate act; the rate-con default-selection rule does not apply). Customer billing e-mails are not offered (the customer copy goes through the existing Documents → E-mail dialog).
- **D11 Optional BOL row in the checklist.** `releaseDocItems` returns `required: boolean` per item and always includes `BOL` (optional when neither the customer's nor the org's list requires it). `DocumentsCard` renders "Bill of lading · optional" for `required:false`, ticked from the same derived presence (no write on generate — the row creation *is* the tick, and the server gate sees it in the same transaction). Required-ness comes from `requiredDocTypesFor(customer, settings)`, i.e. the per-customer "BOL required" the AP/Load Review side already uses.
- **D12 A generated, unsigned BOL ticks "BOL" (matches today's server gate and the spec's "ticks BOL").** The tick row shows the source: "generated v2" vs "uploaded". Not changed: a customer who needs a *signed* BOL still uploads the signed scan (type BOL, `source UPLOAD`), which supersedes nothing (different slot semantic would be a gate change, out of scope). Recorded as risk R2.
- **D13 "Language note" = a select `English only` (default) / `English + Spanish receipt line`** that prints a fixed Spanish rendering of the receipt line under Conditions. The Spanish text is a constant in `bolModel.ts` for Ryne to approve (no machine translation). Assumption — the spec names the option without defining it.
- **D14 Receiving block.** Consignee signature block gets "Pieces received ____ in good order ☐  exceptions ____" and the shipper block "Pieces tendered N" (sum of `qty`, or `Load.pieces`). Seal prints in the carrier block and a "Seal ____" blank when `sealRequired` and none recorded.

## 2. `bolModel.ts` — the pure builder (Lambda-safe: relative, type-only imports)

```ts
export type BolScope =
  | { kind: 'MASTER' }                                  // one BOL listing every stop
  | { kind: 'STOP'; stopId: string }                    // one delivery stop
  | { kind: 'CARRIER'; loadCarrierId: string }          // AT5, multi-carrier only
export interface BolBuildOptions {
  scope: BolScope; includeRates: boolean; language: 'EN' | 'EN_ES'
  brokerPhone?: string | null; terms?: string | null    // settings.trackingContact.phone / settings.bolTerms
}
export function buildBolModel(bundle, customer, division, locations, opts: BolBuildOptions): BolInput
export function bolScopeOptions(bundle): { scope: BolScope; label: string }[]  // dialog list; 1 delivery => only MASTER
export function bolSlot(scope: BolScope, includeRates: boolean): { stopId: string | null; loadCarrierId: string | null; rated: boolean }
export function bolFilename(pro: string, version: number, scope: BolScope, rated: boolean): string // bol-14913-d2-v1.pdf, bol-14913-rated-v1.pdf
export function bolChips(order, load): string[]         // requirement chips, allow-listed
```

`BolInput` (additive over today's): `title`/`scopeLabel` ("BILL OF LADING — Delivery 2 of 3: Kroger, Dallas TX" or "Master — 3 stops"); `broker {legalName, address, phone, mc, dot, logoKey}`; `bolNumber` (= PRO, D-note below) + `shipmentNumber`; `date` (generation date, ISO day); `customer {name, billTo, poRef}` (Bill To from the header strip's chosen `billToId`, existing `billToName`); `shipper`/`consignee: BolParty` (name, address, contact+phone, `appt` window, ready/appt type, refs); `stops: BolStopRow[]` (MASTER only: seq, kind, name, city/state, appt, own refs); `references: BolReference[]` (PO first, then every CUSTOMER/ALL ref, de-duplicated by label+value; stop refs stay on their party); `carriers: BolCarrier[]` (name, mc, driver, driverPhone, truck, trailer, **seal**, `legStopIds`; empty list = none assigned yet; list of one for every existing load) — replaces `carrier: BolCarrier | null`; `lines: BolLine[]` (qty, unit, description, weightLbs, class, nmfc, `hazmat` printed string `UN1203 · Class 3 · PG II · 24h 800-…`); `totals {pieces, weightLbs}`; `declaredValue: string | null` (formatted from `Load.cargoValueCents`, a string precisely so the "no money key" test stays strict); `chips: string[]`; `notes {bol: Order.customerNotes (260), special: form.instructions.special}`; `rates?: {lines:{label, amountCents}[], totalCents}` only when `includeRates`, customer side only; `terms`; `languageNote: string | null`; `signatures {shipper, carrier, consignee}` flags the renderer prints.

Rules the tests pin:
- **Lines**: `Order.freight` of every order (the pinned `frt-main` plus Items). If empty (imported/legacy): one line from `Load.commodity ?? freightDescription`, `Load.pieces`+`piecesUnit`, `Load.weight`, `form.ship.freightClass`, hazmat flag → "Hazmat — see shipper paperwork" when no per-item hazmat; never an empty table (today prints "See attached manifest"). For `frt-main` the unit label comes from `Load.piecesUnit` when the stored `handlingUnit` is the form's default `PALLET` (R6).
- **STOP scope**: consignee = that delivery; shipper = first pickup, plus "Also picked up at:" when several pickups; freight = the stop's own `Stop.pieces/weightLbs` as one line (description from the main line) when set, else all lines with "Shipment total — see master BOL" (Items carry no stop id, so they cannot be split honestly). Refs: order-level on the shipper, that stop's on the consignee. Two deliveries ⇒ two models, distinct slots.
- **MASTER**: shipper = first pickup, consignee = last delivery (today's rule) **plus** the `stops` table, so intermediate stops are visible instead of silently dropped.
- **Chips** (allow-list, in this order): Hazmat, Team, Tarps (+size), Straps/Chains, Liftgate, Inside, Temp control (`tempF` target + min–max, °F; falls back to `form.ship.temp`), Pallet exchange (in/out), Permits, FSMA, Oversize, Escorts, Seal required, Blind, Customs bonded, Labor, High risk, Mass release. Never printed: No broker, Hot, TONU, OSD, notes, roles (commercial/internal).
- `includeRates=false` ⇒ `rates` is `undefined` (key absent). `true` ⇒ only `side === 'CUSTOMER'` lines; a CARRIER line, margin, profit, cost, financials never enter.
- **BOL number = PRO** (spec). A `BOL` reference no longer replaces it; it prints as a ref line "Customer BOL #" (today's override and its test change — open question 3).
- Division letterhead fields per D7; missing logo/address degrade silently to text; missing customer/locations never throw (same tolerance as today).

## 3. Renderer (`bolPdf.ts` on the shared letterhead)

`buildBolPdf(input, {loadLogo}?)`: `resolveLetterhead` once, `drawLetterhead` per page (title "BILL OF LADING", subtitle `BOL <PRO> · <date>`; second line `scopeLabel`). Body order: Customer / Bill To / PO → Ship from | Ship to → (MASTER) stops table → Carrier table (one row per carrier: name · MC · driver · truck · trailer · seal) → Freight table (Qty, Unit, Description, Weight, Class, NMFC, Hazmat; totals row; declared value line) → Requirements chips line → References → BOL notes + Special instructions (260 / 420 chars wrap) → (rates only) a "Charges" table + total, headed "Customer copy — contains rates" → Conditions (+ Spanish line) → **Signatures**: three blocks (Shipper: sign, print name, date/time, pieces tendered; Carrier/Driver: pre-printed driver name, sign, date/time, seal; Consignee: sign, print name, date/time, "pieces received ___ in good order ☐ exceptions ___"). ## 4. Lambda

`SAVE_GENERATED_DOCUMENT` (existing action, additive input): `stopId?`, `loadCarrierId?` (BOL only; validated by `assertPlacement`, a `stopId` must be a stop of `loadId`'s load), `rated?: boolean` → audience `CUSTOMER` instead of `DEFAULT_AUDIENCE.BOL`, `referenceSuffix?` (`[A-Za-z0-9-]{1,20}`, goes into the S3 key and default name). Version/supersede use the D4 slot; D5 guard. Row additions: `stopId`; audit changes gain `stopId, loadCarrierId, rated`. Wire shape of the answer (`{bundle, document}`) unchanged, so the dialog gets the stored row and fresh `bundle.documents`.

`EMAIL_BOL` (new, D9): `{ documentId, to: string[], cc?: string[], message?: string, party: 'CARRIER'|'DISPATCHER'|'DRIVER'|'CUSTOMER' }` → `{ message: ShipmentMessageRecord, emailStatus: 'SENT'|'NOT_SENT', emailError, downloadUrl? }`. Refusals (plain `Error`, like the rest of the Lambda): non-BOL, not ACTIVE, `audience !== 'ALL'`, other shipment, voided shipment, empty `to`, an invalid address (`to[0] must be an email address`), > 20 addresses, > 10 MB. Subject `Bill of lading <PRO>[ — Delivery 2] [ref <shipmentId>]`, body: sender's `message` + the line "BOL attached." signed like the thread (`— <first name>, BCAT Tracking`). Authorization: same caller groups as `SAVE_GENERATED_DOCUMENT`.

Client (`apiClient.ts`): `SaveGeneratedDocumentInput` gains the fields above; `emailBol(input)` via `shipmentAction('EMAIL_BOL', …)`; `auditActivity.ts` labels `EMAIL_BOL: 'e-mailed the bill of lading'`. Download = existing `getShipmentDocumentUrl(s3Key)` (presigned) — no new action.

## 6. Pairing with the multi-carrier plan (feedback 15 / `AT-plan.md`)

MC facts relied on (MultiCarrierPlan, confirmed): several `LoadCarrier` rows `ACTIVE` on one load; additive `LoadCarrier.legStopIds: string[]` (absent/empty = all stops) read through pure `legStopsOf(loadCarrier, stops)` in `src/lib/carrierLegs.ts`; rate con and bills are per carrier; `Load.activeLoadCarrierId` is only the primary pointer.

**Recommendation (cleanest pairing): master BOL by default, per-carrier BOL as an option.**
- One shipment = one PRO = one BOL number; customer and docks read one document; a master BOL's Carriers table lists each carrier with driver/truck/trailer/seal and the stops it covers (legs). The driver of each leg still signs on the Carrier/Driver block — the block repeats once per carrier (two or three rows, not new pages).
- `BolScope 'CARRIER'` (per-carrier BOL) is for handing one driver a page showing only their leg: stops = `legStopsOf(lc, stops)`, shipper = first stop of the leg, consignee = last stop of the leg (a transload site is the consignee of leg 1 and the shipper of leg 2), carrier table = that carrier only, own slot via `loadCarrierId` (versions independent, `documentSection` puts it in the Carrier block, `presentDocTypes` still counts it for the customer gate through an ACTIVE assignment). Offered in the dialog only when ≥ 2 ACTIVE carriers.
- **Sequencing/ownership:** AT1–AT4 build `carriers: BolCarrier[]` (list of one) and the multi-row table already, with `legStopIds` read through a one-line local `legStopIdsOf(lc)` that returns `[]`; **AT5 runs after MC0 (field + `carrierLegs.ts`, per AT-plan.md)**, swaps in `legStopsOf`, enables the CARRIER scope and the Generate-row Rate Con carrier menu (MultiCarrierPlan confirmed: `openSendRateCon` takes an optional `loadCarrierId`, required (no default pick) with 2+ live carriers; AT5 only passes the id). If MC0 lands first, AT1 imports `legStopsOf` directly and AT5 shrinks to the dialog/menu work.

## 10. Risks (ranked)

1. **R1 — BOL on a DRAFT shipment (D5).** Reverses a deliberate Step E rule ("a draft has no paperwork") for BOL only. A DRAFT can be incomplete (created leniently via Save draft) and a BOL generated then goes stale when the order is edited; D6 (saved-only, dirty-blocked) and the Generate row warning limit it, but a later edit does not regenerate or flag the stored BOL. Mitigation: dialog banner "Shipment is still a draft"; Submit order (or any stop/freight edit after a BOL exists) shows a "BOL v1 predates these edits — regenerate" chip comparing `document.uploadedAt` with `shipment.updatedAt`.
2. **R2 — An unsigned generated BOL satisfies the "BOL required" invoice gate (D12).** True today and made more prominent by the tick. A customer that bills on a signed BOL could be released to invoicing on our own printout. Not changed here (it would alter Load Review/AP gating); needs Ryne's call — cheapest fix later: gate on `source !== 'GENERATED'` for customers whose list says "Signed BOL".
3. **R3 — Money on a driver-held page.** Include-rates=Yes is the only path that can put money on a BOL. Held by construction (customer side only, audience CUSTOMER, server refuses `EMAIL_BOL`, thread refuses CUSTOMER docs, slot separate), but the dialog must keep the consequence visible and the tests above are the guardrail; any future "attach to carrier e-mail" feature must keep honoring `audience`.
4. **R4 — Cross-plan collisions in the same hot files** (`handler.ts` ≈ 8.3k lines, `shipmentDocuments.ts`, `GenerateRow`/`DocumentsCard`, `releaseDocs.ts`) with the multi-carrier plan. Mitigated by the single-owner contracts in §6/§8 and serial ordering AT2 → MC handler slices; if MC1 changes `nextVersion/supersede` first, AT1 adopts its signature instead.
5. **R5 — Browser-built PDF dependencies:** logo fetch (≤ 5 s added to preview; failure ⇒ text header), locations not yet loaded (`ensureLocations` must run before the dialog builds, else shipper contact/address fall back to the stop snapshot), stale bundle (D6), and **no layout test exists for `bolPdf.ts` today** — pagination with long item lists and the signature block are the likeliest visual regressions; `bolPdf.test.ts` plus the §9 text extraction are the net. `frt-main` prints "PALLET" for pieces that are cartons because `toFreight` defaults `handlingUnit` (R6: fixed in the builder via `Load.piecesUnit`, root cause in `mapping.ts` left alone).
6. **R7 — E-mail path.** New action means new SES surface: header-injection (validated), unbounded recipients (≤ 20), attachment size (10 MB generated cap), dev SES allow-list (`NOT_SENT` + download link, same as rate con). The thread's single-recipient `to` limitation and missing address validation in `SEND_SHIPMENT_MESSAGE` is a **pre-existing** problem left untouched; flagged for a separate fix because the tracking agent depends on it.
7. **R8 — Template guard.** Zero schema/GSI/resource change by design (D1); any slice that "just adds an enum value" (e.g. `ShipmentMessage.kind BOL`, `ShipmentDocument.type BOL_RATED`) breaks that and needs Main's sign-off against the 1,000,000 B / 500-resource limits first.
