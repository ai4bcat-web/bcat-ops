# Step C — Carriers & booking (dev)

## Architecture and scope

Planned by Claude Fable (`reviewer`, planning-only, as in A/B). Sources: `MVMNT_TMS_SPEC.md` §3.3, §6.5, §6.7, §7 row C, §8.2; `TMS_DESIGN.md` §4.4, §4.8, §5, §6, Phase 2; `TMS_BUILD_BRIEF.md` hard rules. Four new models — **Carrier** (outside carriers only; own fleet stays Driver/Equipment and books through the existing `ASSIGN_ASSET` picker), **CarrierContact**, **CarrierPaymentMethod**, **CarrierDocument** — plus additive fields on `LoadCarrier`, `Load`, `TmsSettings`. New models: `allow.authenticated().to(['read'])`, subscriptions disabled, Lambda-written. Money integer cents, percentages bps, timestamps ISO. Booking is a gated `BOOK_CARRIER` in `tmsShipmentActions`; carrier CRUD is a new `tmsCarrierActions` Lambda (router cloned from `tmsDirectoryActions`). **Correction to the brief:** `blueink-sync` is the Blue Ink Tech ELD, not e-sign; the reusable e-sign pattern here is `DocumentSignatureRequest` + `onboarding-portal-api` `signGet`/`signSubmit` (tokenized link, browser-built signed PDF). C copies that for rate cons — no new dependency (jsPDF/pdf-lib already present). Highway/RMIS/MyCarrierPackets: manual status fields in C, integration in J.

## Pure libs (`src/lib/`, relative imports, Lambda-shared)

`carrierEligibility.ts`: `evaluateCarrierBooking({carrier, documents, load, financials, settings, now, isAdmin})` → `{blocks, warnings}` of Reason: `STATUS_NOT_ALLOWED`, `DO_NOT_USE`, `AUTHORITY_INACTIVE`, `ALREADY_COVERED`, `NEGATIVE_CARRIER_CHARGE` (always block); `INSURANCE_EXPIRED` (required policy `expiresAt` < pickup date, or none of that type; block); `CARGO_VALUE_EXCEEDS_INSURANCE`, `INSURANCE_UNVERIFIED` (no CARGO policy), `COST_EXCEEDS_TOP_SPEND` (block non-admin, warn admin); `INSURANCE_EXPIRING` (within `insuranceWarnDays`), `MISSING_DOC`/`DOC_EXPIRED` per `requiredCarrierDocs`, `MISSING_REQUIRED_FIELD` per `bookingRequiredFields`, `DOUBLE_BOOKED` (same carrier ACTIVE on another load with the same pickup day) — warn. `insuranceState(policy, now, warnDays)` → UPCOMING·ACTIVE·EXPIRING·EXPIRED; `oosBps(inspections, oos)`. `quickPay.ts`: `tierFor(days, tiers)` exact match; `quickPayFee(rateCents, feeBps)` half-up; `netPayable`. `carrierRateCon.ts` (jsPDF + autotable like `payPdf.ts`): `buildRateConPdf(bundle, loadCarrier, carrier, division, terms)` — broker header from Division (legal name/MC/remit), carrier block, stops with CARRIER-visible references, equipment/commodity/weight, CARRIER charge lines + total + quick-pay line, required-field blanks, `rateConTerms` (customer override else org), signature block; `stampSignature(pdfBytes, {name, ip, at})` with pdf-lib appends one page (browser-side, as the driver signing flow). `carrierStatus.ts`: PENDING→REVIEW·ACTIVE·INACTIVE·DO_NOT_USE; REVIEW→ACTIVE·INACTIVE·DO_NOT_USE; ACTIVE→INACTIVE·DO_NOT_USE; INACTIVE→ACTIVE·DO_NOT_USE; DO_NOT_USE→INACTIVE (admin); INACTIVE/DO_NOT_USE need a reason; `effectiveStatus(carrier, now)` shows INACTIVE/EXPIRED_INSURANCE when every CARGO policy is expired (derived, never written).

## Lambdas

**`tmsCarrierActions`** (new; mutation `tmsCarrierActions(action, input: AWSJSON)`, owner/ADMIN/`page-carriers`, CAS on `version`, AuditLog `EntityType` + `'Carrier'`): `UPSERT_CARRIER` (normalizedName/MC/DOT dedupe, policies ≤50 element-validated, create = PENDING, ACTIVE on create admin-only, status not changeable here); `SET_CARRIER_STATUS {id, expectedVersion, status, reason?, note?}` per table (ACTIVE LoadCarriers on un-dispatched loads get a `bookingWarnings` note, never auto-bounced); `UPSERT_CONTACT`/`ARCHIVE_CONTACT`; `UPSERT_PAYMENT_METHOD`/`ARCHIVE_PAYMENT_METHOD` (one preferred; FACTOR needs `factorName`); `PREPARE_DOCUMENT`→presigned PUT / `COMMIT_DOCUMENT` (HEAD-verify, conditional Put; `vendor-ap-intake` protocol) / `DELETE_DOCUMENT` (ADMIN or uploader); `SAVE_CARRIER_SETTINGS` (admin; tiers ascending by days, bps 0..10000). **`tmsShipmentActions` +** `BOOK_CARRIER {loadId, expectedUpdatedAt, carrierId!, carrierRepId?, carrierRateCents!, charges?, contactId?, dispatcher*, driver*, driver2*, truck/trailer/plates/vin, equipmentType, trackingProvider, quickPayDays?, paymentTermsDays?, acknowledgeWarnings[]}` — SOURCING + truckload + no ACTIVE carrier; blocks refuse; every warning must be acknowledged (non-admin cannot acknowledge admin-only ones); one transaction: LoadCarrier CARRIER ACTIVE with profile snapshot + terms, CARRIER LINEHAUL and extra lines, LoadFinancials recalc, `Load.assignmentType CARRIER/activeLoadCarrierId/carrierName/status BOOKED`, `Carrier.loadCount/lastLoadAt`; audit records blocks/warnings/acknowledged. `ASSIGN_CARRIER` stays for name-only entries and refuses a `carrierId`. `SET_QUICK_PAY {loadCarrierId, quickPayDays|null}` (ACTIVE/TONU; refused after `chargesFinalizedAt`/`frozenAt`). `SEND_RATE_CON {loadCarrierId, pdfBase64, to[], cc?, expiresHours?}` — ACTIVE only; stores `rate-confirms/carrier/{loadId}/{loadCarrierId}-v{n}.pdf`, CarrierDocument RATE_CON GENERATED, 32-byte url-safe token, `rateConStatus SENT`, SES email (`driver-pay-emailer` MIME pattern) linking `/sign/rate-con/:token`; re-send voids the prior token, bumps `rateConVersion`. `VOID_RATE_CON`. `DISPATCH_LOAD {loadId, dispatchedAt, pickupEtaAt, driver*, truck*, trackingProvider, nextCheckCallAt?, nextCheckCallNote?, note}` — BOOKED + ACTIVE carrier, warns when `rateConStatus ≠ SIGNED`, load → DISPATCHED via the existing table. `REMOVE_LOAD_CARRIER`: `reason` becomes enum + note (BOUNCED CARRIER_CANNOT_TAKE·GAVE_BACK·REJECTED_RATE_CON·OTHER; TONU CUSTOMER_NOT_READY·CONSIGNEE_NOT_READY·FORGOT_TO_BOUNCE·OTHER) and voids an open rate con. **`rate-con-sign-api`** (new public Function URL, `dispute-portal-api` shape, `PORTAL_ORIGINS` CORS, IAM read via `rateConToken` GSI, S3 get/put): `get` → status/expiry/required fields + presigned unsigned PDF; `submit {token, signerName, fields, pdfBase64}` → once-only/expiry checks, signed PDF to `rateConKey`, CarrierDocument RATE_CON SIGNED, `SIGNED` + `rateConSignedAt`, blank driver/truck fields filled from `fields`, AuditLog; `decline {token, reason}`. Per-token rate limit like `OnboardingInvite.requestCount`.

## Client and UI

`apiClient.ts`: `carrierAction<T>()`, `listCarriersByStatus`, `carriersByMc/Dot`, `getCarrierBundle(id)` (carrier, contacts, payment methods, documents, LoadCarriers by `carrierId` GSI); hooks `useCarriers(view)` (poll like `useDirectory`), `useCarrier(id)`. Settings gains a Carrier booking card for the new TmsSettings fields.
