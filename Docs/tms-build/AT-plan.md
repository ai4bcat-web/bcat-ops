## 2. Decisions for Ryne (recommended default first; build proceeds on the default unless he overrides)

| # | Decision | Recommended default | Alternative / cost |
|---|---|---|---|
| **D1** | **Where do several carriers live?** | **N ACTIVE `LoadCarrier` rows on ONE `Load`** (the Load keeps all stops; each carrier optionally names the stops it covers). Reuses booking gates, rate con, tokens, bills, charges, tracking links unchanged. | One `Load` per carrier (existing multi-leg): every per-Load structure (financials, charges, stops, create form edits one Load) would have to split a single customer order across Loads; transload stops would be duplicated. Much larger blast radius. |
| **D2** | **Own fleet next to brokered carriers on the same Load** (feedback 15 asks for it) | **Server refuses it in v1**: a Load is either one own-fleet driver (today, exactly) or 1-4 outside carriers. UI shows "+ Add carrier" disabled on an own-fleet load with the reason. Why: `ownFleetLoadPatch` writes the driver on every stop and settlements pay a % of the whole `Load.rate`; a mixed load would overpay the driver by the brokered leg's revenue. | Allow it after a pay-base field exists (`LoadCarrier.legRevenueCents` for the own leg) and the settlement engine reads it (separate, pay-engine step; needs Ryne's rule for the revenue split). Until then Ivan Cartage + brokered legs = two shipments (or two Loads/legs, already supported). |
| **D3** | **"Release creates one bill per carrier."** Today release *requires* a recorded bill per ACTIVE outside carrier (gate 222-232) and recording is a human act that finalizes charges and re-runs commissions; AG deliberately never records (AG-plan D10). | **Keep the order**: bill is recorded first, then release. Multi AP records = one `LoadCarrier` AWAITING_INVOICE row per carrier from the moment each is added (already how booking works, `apOpen:'OPEN'`), one `CarrierBill` per carrier when recorded. Load Review gets a side-by-side bills panel and one **"Record all bills"** button (sequential `RECORD_BILL`, each its own transaction, stops on first error and names the carrier). Release is refused while any carrier has no rate or no recorded bill. | Auto-record IN_REVIEW bills at release: inverts the gate (bill would have to exist to pass it), hides the human check on carrier invoices, and finalizes charges silently. Not recommended. |
| **D4** | Rate con required for release | **Every** ACTIVE outside carrier's rate con must be SIGNED (today: any one). Message names the carrier. Single-carrier text stays byte-identical. | Keep "any signed": cheaper, but a signed rate con for carrier A would waive carrier B's. |
| **D5** | Tracking mode per carrier | **Per shipment by default (no change), optional per-carrier override**: JSON `LoadCarrier.trackingPrefs` (absent = inherit the shipment's), `TrackingModeControl` in each carrier block edits the override. Slice MC6, ships after the money slices. | Per shipment only (zero schema, loses "tracking read for that carrier"). |
| **D6** | Status machine | No new statuses. Load stays BOOKED when ≥1 live carrier, DISPATCHED when the first carrier is dispatched, SOURCING only at zero live carriers; removing one of two never uncovers the load. Stop events move it as today. Per-carrier progress is derived (`carrierPhase`, §4), not stored. | Per-carrier status field: stored state that can drift from stop times. |
| **D7** | Cap | **4 active carriers per Load** (transaction item budget, hover/board legibility). | Higher cap needs a re-check of the 100-item `TransactWriteItems` budget in `repriceShipment`. |
| **D8** | Lane history | Loads with ≥2 live carriers are written to `LaneRateSample` as `excluded` (a split load is not a lane price). | Include with summed cost: distorts lane stats. |
| **D9** | Meaning of empty `legStopIds` | Empty/absent = covers **all** stops (two carriers with no legs = split freight, both whole route). Legs only narrow. | Require legs when ≥2 carriers: extra clicks for the common "two trucks, same lane" case. |

## 3. Data model (additive; zero new models, zero new GSIs)

Budget (amplify data guard 1,000,000 B, current 963,479 B, 460/500 resources): fields on existing models cost ~0 B (AG-plan R10:
one model +3,839 B, models+GSIs +9,602 B). **This plan adds none of those.** Measure the template before/after with the BUILD_LOG
2026-11-04 method; if the two fields below move it by more than ~500 B, stop and re-plan.

**`LoadCarrier` (2 optional fields):**
- `legStopIds: a.string().array()` — `Stop.id` values from `Load.stops` this carrier covers. Absent/empty = all (D9). Validated on write (every id exists in the Load's stops; edited through `UPDATE_LOAD_CARRIER_DETAILS`, which gets the key and an array validator). Order is not stored: stops keep their sequence.
- `trackingPrefs: a.json()` — optional per-carrier override of `Shipment.trackingPrefs` (D5, MC6 only; absent = inherit).

**Everything else is reused, not added:**
- Per-carrier rate = that carrier's CARRIER `LoadCharge` lines (`loadCarrierId`), cached on the row (`carrierRateCents`, `costCents`) by `carrierCachePatch`, one per live carrier.
- **Accessorial "Paid to"** = the CARRIER line's `loadCarrierId`; "Not paid to a carrier" = no CARRIER line (customer-only). Paid-only = a CARRIER line with no customer twin. The form's `AccessorialLine` keeps one row = up to two LoadCharges and gains `paidTo: string` (form slot key, see below) replacing the display-only `carrierKey`.
- Bills: `CarrierBill` unchanged (already `loadCarrierId`-keyed).
- `Load.activeLoadCarrierId` = **primary** = lowest-`sequence` ACTIVE carrier (written on add/remove only; the projector and notifier never re-point it). `Load.carrierName` = primary's name. `assignmentType` = `CARRIER` while any outside carrier is live (own fleet stays exclusive, D2).
- `Order.formExtras` (JSON, `v:1`, allow-list in `orderForm.ts` 112): add optional `carriers: [{ slot, loadCarrierId?, draft?: {rateType,hours,lhRateCents,payPct,maxRateCents}, originCity, originState, emptyMiles, driverEmail1, driverEmail2 }]`. Legacy `rates.carrierDraft` and `carrier.*` keep being read as slot 0 (see read rule).

**Backfill-free read rule (the single compatibility rule).** `liveCarriersOf(loadCarriers, loadId)` returns the ACTIVE rows for that Load ordered by `sequence`. A Load with one ACTIVE row, or none, behaves exactly as today: `legStopIds` absent => all stops; no `carriers` extras key => slot 0 built from `carrier` / `rates.carrierDraft`; a CARRIER line with null `loadCarrierId` is attributed to the sole live carrier (as `repriceShipment` does now) and **refused when there are two or more**. Nothing is migrated, no script, no data write on existing loads.

**Form slot model.** `values.carriers: CarrierSlot[]` (client key `slot`, plus `loadCarrierId` once booked, plus the existing carrier block fields and a per-slot rate row `{rateType,hours,lhRate,payPct,maxRate}`); `values.carrier` / `values.rates.carrier` become slot 0 views. Local drafts (`draftStore.ts`) written before this change are upgraded on read (wrap the old fields as `carriers[0]`).

## 5. Lambda changes — `tms-shipment-actions` (one owner, `handler.ts` is 354 KB) and `tms-finance-actions`

- **`ADD_CARRIER`** (new; thin wrapper over `bookCarrier(options.additional)`; typed-name path over `assignCarrier(additional)`). Input = BOOK_CARRIER's plus `legStopIds?`. Rules: Load status must be SOURCING, BOOKED or DISPATCHED (not DELIVERED/CANCELED/voided); live count < 4 (D7); no live OWN_ASSET row (D2); the same directory carrier twice only with disjoint non-empty legs; financials not frozen; runs `evaluateCarrierBooking` with `additional`. Writes (one transaction): new `LoadCarrier` (`apStatus:'AWAITING_INVOICE'`, `apOpen:'OPEN'`, `sequence = max+1`, `legStopIds`), its LINEHAUL `LoadCharge` with `loadCarrierId`, Load patch only for what changed (`activeLoadCarrierId` only if none, `assignmentType 'CARRIER'`, status unchanged unless SOURCING -> BOOKED), ladder mirror = least-advanced rung of live rows, audit row, then `rederiveShipmentStatus`. It does **not** retire anyone.
- **`BOOK_CARRIER` / `COVER_CARRIER` / `ASSIGN_CARRIER` / `ASSIGN_ASSET`**: unchanged semantics when called without `additional` (replace). With ≥2 live carriers they refuse (`Remove a carrier first or use ADD_CARRIER`) rather than silently retire one.
- **`REMOVE_LOAD_CARRIER`**: if other ACTIVE rows remain: retire only this row, bounce deletes only its lines (existing), void its rate con and revoke its ping link (existing), re-point `activeLoadCarrierId` to the new primary, `carrierName` to the primary, ladder mirror to the least-advanced rung, **do not** set SOURCING / `NEED_TO_COVER` / `trackingProvider NONE`, do not clear the check-call reminder. Zero remaining = today's path. Bounce still refused while that carrier has a bill (existing).
- **`UPDATE_LOAD_CARRIER_DETAILS`**: accepts `legStopIds` (validated by `validateLegs`); `trackingPrefs` in MC6.
- **`SAVE_ORDER_FORM` / `RECALC_CHARGES` / `UPDATE_ORDER_DETAILS` (`repriceShipment`)**: every CARRIER line must name a live carrier of this Load (explicit `loadCarrierId`); null is defaulted only when exactly one is live, refused otherwise. Re-cache **every** live (and TONU) row with `carrierCachePatch` (own lines only); `assertFinalizedChargesUnchanged` (already keyed per finalized `loadCarrierId`, 6236) so a recorded bill on A does not freeze B. `LoadFinancials.carrierRateCents/costCents` stay the Σ over carriers. `formExtras.carriers` accepted by the allow-list.
- **`UPDATE_CARRIER_CHARGES`, `SET_QUICK_PAY`, `ENTER_DRIVER_INFO`, `MARK_RATE_CON_SIGNED`, `SEND_RATE_CON`, `VOID_RATE_CON`**: already per `loadCarrierId`. `SEND_RATE_CON` change: subject/filename carry the carrier name when ≥2 live; the shipment thread (one `threadKey`, one tracking address) is shared. Audit unchanged.
- **`DISPATCH_LOAD`**: optional `loadCarrierId` (required when ≥2 live); stamps that row's `dispatchedAt`; Load -> DISPATCHED on the first dispatch. `assertOwnAssetDriver` paths untouched.
- **`READY_TO_INVOICE` / release / `GENERATE_INVOICE`**: legs already flow through `_shared/releaseGateInput.ts`; add `carrierRateCents` there. Release marker rule (Load Review only) unchanged.
- **`tms-finance-actions`**: no new action. `RECORD_BILL` unchanged; MC5 adds nothing server-side except tests. "Record all bills" is client sequencing.
- **Lane samples** (`laneSamples.ts`): `excluded` when ≥2 live carriers (D8).
- **Not touched:** `tms-aljex-import` (writes single legs), `tms-ap-inbox` write paths, `rate-con-sign-api`, `tracking-api`, DAT postings/offers (`acceptOffer` books via the replace path).

## 8. Risks

1. **Money correctness.** (a) PERCENT base summed across carriers (fixed in `shipmentCharges`). (b) An untagged CARRIER line silently defaulted to "the active carrier" or printed on every rate con (`repriceShipment` 6312, `RateConPanel` 108): both become explicit/refused. (c) Margin/commission must use gross, not net or billed. (d) Σ `PCT_OF_CUSTOMER` rows over 100 % pays more than the customer LH: show a warning chip in the form (cost over revenue is already only a warning today, so it is not made a block). (e) Cents drift: only integer sums of already-rounded lines.
2. **Own fleet / driver pay.** Mixed own+outside would overpay the driver (settlement % of whole `Load.rate`, driver on every stop). Mitigated by D2 (server refusal) and the unchanged own-fleet tests. If Ryne overrides D2, a pay-base field and settlement change is a prerequisite, not a follow-up.
3. **Status machine / single pointers.** Removing one of two carriers must not set SOURCING, null the pointer or clear the check-call reminder; `activeLoadCarrierId` readers keep seeing the primary. A stale pointer after a bounce of the primary is the likeliest bug: re-point in the same transaction and test it.
4. **Release gate regressions on existing single-carrier loads.** Any change to messages/ordering breaks `releaseGate.test.ts` and live harnesses. New rules apply only when ≥2 legs (RATE_CON) or add a new code (rate missing) that cannot fire where a bill exists; one-carrier sentences are byte-identical.
5. **Schema/GSI cost and deploy order.** Two optional fields, no model, no GSI, no new Lambda/IAM; guard against the 1,000,000 B template (963,479 B now). Selections must use the existing pre-deploy field fallback in `apiClient.ts` (`LOAD_CARRIER_FIELDS` is read before the schema deploys); ship MC0 schema+libs first.
6. Form complexity: the slot model touches `model/mapping/pipelines/validation/draftStore/rail` (the most-tested area); keep slot 0 as the legacy shape to bound the diff.
7. Concurrency: two people adding carriers at once. `ADD_CARRIER` takes the Load's `expectedUpdatedAt` (CAS) like `bookCarrier`; the second gets the existing conflict error.
8. Dashboard/charts-by-carrier attribute a Load to its primary carrier (`dashboardCharts.ts` 305): known limitation, documented, not fixed here.
