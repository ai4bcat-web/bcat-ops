**Judgement calls.** (1) **One new tab, not eleven.** §8.3 is a left-hand settings menu in MVMNT; this strip is horizontal and already carries nine entries. Eleven more would wrap on a 1,280px window and bury Users. So the four pages that are *identity, money paperwork, look and plumbing* go under one tab with an inner strip — the `ai-agents/*` shape (`BrokeragePage.tsx:99`, `AiAgentsPage.tsx:45`) — and the four that are *house rules about freight* become cards on the Settings tab beside the eleven house-rule cards already there. Rejected: a `settings/*` wildcard with its own sub-nav, which would move the Settings tab off the index path `''` and break the five redirects at `App.tsx:324-353`; and a second top-level nav row, which rule 3 forbids. (2) **Company details are the `Division` row, not a copy on `TmsSettings`.** Five document builders already read the brokerage's legal identity from `Division` (`invoiceBuild.ts:288-306, 528-534`, `carrierRateCon.ts:124-128`, `documentData.ts:369-374`, `carrierBill.ts:581-585`). A second copy on the settings singleton would be a field that disagrees with the invoice within a week — exactly the drift `src/lib/branding.ts` was written to end. So L **promotes** `DivisionCard` into the Company and Billing pages, renames the card's framing from "Legacy division keys" to what it is (the billing entities), adds the eleven fields §8.3 asks for, and marks exactly one row `isPrimary` — that is MVMNT's "Billing Entity selector: parent org or companies". `OwnershipDivision` (`resource.ts:2350`) stays what R made it: the tag tree that says which business owns a shipment, not who is on the invoice. (3) **No new Lambda.** Every write L needs is `SAVE_SETTINGS` or `SAVE_DIVISION` on `tmsDirectoryActions` (`handler.ts:2473-2475`), plus three new actions on the same router — `ROTATE_WEBHOOK_SECRET`, `PREVIEW_IMPORT`, `RUN_IMPORT` — because that router already owns Customer, Location, Division and TmsSettings, already holds the SSM client and the `parameterNameFor` helper from J, and already has the audit writer. A spreadsheet is parsed **in the browser** (the file never leaves the staff machine until the rows are validated) and submitted as JSON rows in pages of 200, which keeps the 30 s router inside its budget and needs no new runtime. Rejected: a dedicated `brokerage-actions` Lambda (one more function in the data stack for eleven forms); a Lambda-side XLSX parse (a new dependency, brief `:62`, for no gain). (4) **Import is directory-only in L.** §8.3's entity list includes `shipment`, but a shipment import claims PROs, and N1 (`brief:404-415`) is the step that owns the Aljex export with its receivables and payables. L ships the framework — upload, header mapping with suggestions, validate, dry run with counts and conflicts, execute, per-row error report, idempotent re-run, audit row per job — and the seven directory entities; N1 adds the shipment/AR/AP mappers on top of the same `ImportJob` model and the same four-step UI. Saying so now is cheaper than building a shipment importer twice. (5) **The notification catalog is code, the subscriptions are data.** The events are whatever the app can actually emit today — the six `ShipmentNotice.kind` values (`resource.ts:2102`), check-call due/overdue (`LoadCheckCall`, `:1929`), document required and POD received (`ShipmentDocument`, `:2039`), the AR and AP ladder transitions, invoice sent/paid, a workflow exception opening (`WorkflowRun.exceptionOpen`, K) and an integration going unhealthy (`Integration.health`, J) — so `EVENT_CATALOG` is a frozen array in a pure lib, and only the *subscriptions* (who, which channel) are stored. A catalog in the database would be a table of strings nothing can produce. Channels: **EMAIL** and **IN_APP** are wired by existing senders, **WEBHOOK** is wired by L, **SMS** is listed and refused with "the dispatch number is for drivers" until P8 says otherwise, **PUSH** is not offered (no mobile shell for staff). (6) **White-label ships as a request, not a connection.** See *What L cannot finish*. (7) **Brand logos are not a public bucket prefix.** The public tracking and quote pages are unauthenticated and served through `tracking-api`; `storage/resource.ts` grants no guest access anywhere and L does not start. `brand/*` is `authenticated.to(['read'])` + staff write, and a public page gets its logo as a presigned URL from the API that already renders it. (8) **Account is read-only and honest.** It prints what the stack is — branch, Amplify app id, the data-stack template size against the 1 MB cap, the table suffix, region, the deployed commit, which Lambdas exist, which integrations are CONNECTED / STUB / NOT_CONNECTED from the J rows, and the Anthropic model in use — and says in one line that BCAT has no subscription because BCAT owns the software.

**Corrections to the spec from the code.** §8.3's *Users* page wants a "seat count + prorated seat charge": there is no billing relationship to prorate (see below), so the page states the user count and the Cognito pool, and nothing else. §8.3's *Account* page is MVMNT's Stripe portal; row L already says "BCAT has no subscription; show stack/environment info instead", and L does exactly that. §6.7:287's *Base + Allowed currencies* has no consumer — every amount in this repo is USD cents with no currency column on `Invoice` (`resource.ts:1699`), `CarrierBill` (`:1807`) or `LoadCharge` (`:1659`) — so L stores nothing for it rather than adding a field that silently does not convert; the Billing page says so in a line. §6.7's *Postal code aliases* is already built (`PostalCodeAliasesCard`, J, `TmsSettings.postalCodeAliases` `:1134`). §8.3's *Commissions* is Step I (`commissionPlans` `:1120`, `CommissionPayPeriod` `:2554`) and is not re-planned. §8.3's *Teams* "per-team sender addresses" are stored but unused: `teams.ts:19` says "wired to SES in J/L", and the truthful state after L is still **stored, not sending** — SES is denied to every Lambda on the dev stack (J finding, repeated in K), so L wires the *precedence* (team slot beats org default) into the one place that composes an outgoing message and leaves the send path where N3 will find it. §8.3's "blocked LTL carriers" presumes an LTL carrier list; `Carrier` has no `carrierType` (`resource.ts:2588`), so the field stores carrier ids chosen from the existing directory and the help text says it applies when LTL rating is live (SMC3, §8.1). §8.3's consolidation "hazmat mode" presumes a hazmat flag; `Shipment` has none, so the rule is stored and the card says it is inert until a hazmat field exists — the J "stored now, read by nothing" convention (`resource.ts:1126-1128`), stated on the card rather than hidden.

## Schema (`amplify/data/resource.ts`, additive)

**`TmsSettings` — 17 new fields in one block** commented `// ── My Brokerage (Step L) ──`, after `aiAgents` (`:1142`), every one optional, nothing renamed:

*Branding (8).* `brandLogoSquareKey: a.string()`, `brandLogoWideKey: a.string()`, `brandLogoDocumentKey: a.string()` — S3 keys under `brand/`, validator `optionalString(v, 300)` plus a prefix check that the key starts `brand/` (a key pointing at `invoices/` would make the logo a document leak). `brandAccent: a.string()` — one of YELLOW·BLUE·TEAL·RED·PURPLE·ORANGE, validator `optionalEnum(v, BRAND_ACCENTS, 'brandAccent')`. `brandTheme: a.string()` — DARK·LIGHT·SYSTEM, same validator; DARK is the shipped shell and the only one with a stylesheet, so LIGHT and SYSTEM are refused with "only the dark theme is built" until there is a second one. `brandSenders: a.json()` — `{ shipment?, rateCon?, quoteReply?, customerInvoice?, remittance? }`, the **same five slots** as `TEAM_SENDER_SLOTS` (`teams.ts:20-26`) so a team override and an org default can never name different message types; validator `validateBrandSenders` reuses `teams.ts`'s `EMAIL_RE`. `emailSignatureTemplate: a.string()` — ≤ 4,000, tokens `{name} {title} {phone} {company}`, validator refuses an unknown `{token}` (the `{url}`/`{number}`/`{link}` convention already enforced on `trackingSmsTemplate` `:1068`, `invoiceEmailTemplate` `:1085`, `quoteEmailTemplate` `:1105`). `whiteLabel: a.json()` — `{ domain, status: 'NOT_REQUESTED'|'PENDING'|'VERIFIED'|'FAILED', records: [{type,name,value}], requestedAt, requestedBy, checkedAt, failureReason }`; the validator accepts only `domain` from the caller and **computes** `records` and `status` server-side, because a browser that could post `VERIFIED` would be a badge that means nothing.

*Customer settings (2).* `customerPortalDefaults: a.json()` — `{ ltlQuoting: 'OFF'|'RATE_CARD'|'SMC3', portalDispatchMode: 'OFF'|'QUOTE_ONLY'|'FULL', portalStatusMask: string[], blockedLtlCarrierIds: string[], defaultQuoteNotes: string }`, validator bounds the arrays at 50 and checks the status mask against the shipment status vocabulary (`MVMNT_TMS_SPEC.md:296`, already a constant in `src/lib/shipmentStatus.ts`). `customerTags: a.json()` — `[{ key, label, color }]` ≤ 50, keys unique, `^[A-Z0-9_-]{1,24}$/i` (the `TEAM_KEY_RE` shape, `teams.ts:39`), colour from the theme's token list.

*Carrier documents (2).* `rateConTemplate: a.json()` — `{ overrideDefaultTerms: boolean, extraTerms: [{title, text}] (≤ 50, title ≤ 120, text ≤ 4,000), termsHtml: string (≤ 20,000, sanitised server-side to a tag whitelist), hideRep: boolean, legalPageBreak: boolean, requiredDocs: string[] (the `CarrierDocumentType` vocabulary, `resource.ts:2729`), requiredFields: string[] }`; `requiredFields` supersedes nothing — `rateConRequiredFields` (`:1053`) stays the source for the signing form and the template reads it, so the two cannot drift. `carrierAgreementTemplate: a.json()` — `{ bodyMarkdown (≤ 20,000), requiredDocs: string[], signatureBlock: string, version: integer, updatedAt, updatedBy }`; `version` is bumped by the validator **only when the body actually changed**, the `bumpMemory` rule K already proved (`validateAiAgents`, `handler.ts:1573-1576`), so a signed agreement can always name the version it was signed under.

*Consolidation (1).* `consolidationRules: a.json()` — `{ rules: [{ category, severity: 'BLOCK'|'WARN'|'OFF', threshold?: integer, unit?: string }], hazmatMode: 'NEVER'|'SAME_CLASS'|'ALLOW', onHold: 'BLOCK'|'WARN' }`; categories are a frozen list (`CUSTOMER_MISMATCH`, `TEMPERATURE`, `WEIGHT_TOTAL`, `STOP_COUNT`, `PICKUP_WINDOW_DAYS`, `EQUIPMENT_MISMATCH`, `HAZMAT`, `ON_HOLD`), one rule per category, thresholds are integers in the unit the category declares (pounds, stops, days).

*Notifications (3).* `notificationSubscriptions: a.json()` — `[{ event, channel: 'EMAIL'|'IN_APP'|'WEBHOOK', audience: {kind: 'ROLE'|'TEAM'|'USER', value}, enabled }]` ≤ 200, `event` must be in `EVENT_CATALOG`, `audience.value` must be a known role key (`roles.ts`), team key (`TmsSettings.teams`) or staff e-mail. `notificationWebhooks: a.json()` — `[{ id, url, events: string[], secretRef, secretLast4, active, createdAt, createdBy, lastDeliveryAt, lastStatus, failureCount }]` ≤ 10; `url` must be `https:` and must not resolve to a private range by literal form (no `localhost`, no `10./172.16-31./192.168.`, no `169.254.`), `secretRef`/`secretLast4` are written by the Lambda and **ignored if the caller sends them**. `notificationDefaults: a.json()` — `{ pauseAll: boolean, quietHours: {start, end, tz} | null, fromAddress }`.

**`Division` — 11 new fields**, all optional, written by `SAVE_DIVISION`: `taxId` (≤ 32, EIN/tax id), `phone` (≤ 32), `physicalAddress: a.json()` (Address, distinct from `remitToAddress` which is where cheques go), `primaryContact: a.json()` (`{name, title, email, phone}`), `billingContact: a.json()`, `payablesContact: a.json()`, `termsUrl` (≤ 300, must be `https:` — printed on every invoice, §8.3), `paymentInstructions: a.json()` (`{ US: {ach, wire, check}, CA: {eft, check}, MX: {spei, check} }`, each a short free-text block; these are the instructions already printed on the invoice, so they are not a secret and are stored as written — the card says so), `invoiceVerbiage` (≤ 2,000, printed under the instructions), `logoKey` (≤ 300, `brand/` prefix, this entity's document logo), `isPrimary` (boolean — the parent org; the validator refuses a second `true` and demotes nothing silently).

**`TmsSettings.paymentTerms`** is the seventeenth field and the Billing page's only one: `a.json()` — `[{ key, name, days, description, quickPayFeeBps, apOnly, doNotUse }]` ≤ 50; `days` 0..180, `quickPayFeeBps` 0..2000, keys unique and slugified, a `doNotUse` term may not be the default. Eight branding + two customer + two carrier-document + one consolidation + three notification + this one = **17**.

**`ImportJob`** (new model): `entity!` (CUSTOMER·LOCATION·CARRIER·CARRIER_FACTOR·CHARGE_CODE·PAYMENT_TERM·VENDOR_CONTACT), `status!` (DRAFT·VALIDATED·DRY_RUN·APPLIED·FAILED), `fileName`, `fileHash` (sha256 of the uploaded bytes — the idempotency key), `mapping: a.json()` (`{sheetHeader: fieldName}`), `rowCount`, `counts: a.json()` (`{created, updated, skipped, errored}`), `errorKey` (S3 key of the per-row error CSV under `imports/`), `dryRun: a.boolean()`, `note`, `createdBy!`, `appliedAt`, `appliedBy`. `id` = `imp:<sha20(fileHash)>:<entity>`, written with a conditional put so re-running the same file against the same entity is a no-op that returns the first job — the `WorkflowRun` dedupe shape (K, `resource.ts:1245`) and the `IntakeItem` one before it. **No GSI**: a handful of jobs, `list` is the only read. `.disableOperations(['subscriptions'])`, `allow.authenticated().to(['read'])`.

**Storage** (`amplify/storage/resource.ts`): two prefixes on the existing bucket, both `authenticated.to(['read'])` + `STAFF_GROUPS.to(['read','write','delete'])` — `brand/*` (logos, ≤ 10 MB each per §8.3, enforced client-side and again by a `contentLength` check before the key is accepted) and `imports/*` (the uploaded sheet and the error CSV). Neither is public; the `shipment-docs/*`/`invoices/*` precedent (`:139-153`) is read-only to authenticated users and nothing here is looser.

**Template budget, measured.** `node scripts/measureDataTemplate.mjs` on `dev` at the start of L: **785,735 bytes, 214,265 under the 1,000,000 cap** (94 templates; the directive stack is 134,801). L's cost is one model with no GSI and no new function — K's +21,889 bought a model with **three** GSIs plus a new Lambda with its grants and its Function URL, and the per-model floor in this schema is the six CRUD resolvers plus the table, so **L is estimated at +7,000 to +9,000 bytes**, leaving ≥ 205,000 free. New fields on existing models cost nothing in the data *template* (they land in the AppSync schema asset, which is hashed separately — the lesson of `BUILD_LOG.md:956-995`); new actions on existing routers cost nothing; the two storage prefixes land in the storage stack, not this one. **Drop order if the measurement after the schema change says otherwise:** (1) `ImportJob` becomes `TmsSettings.importJobs` JSON capped at 20 rows with the error CSV still in S3 — the model is convenience, not correctness, and buys back the whole cost; (2) the import page defers wholesale to N1 and L ships the mapping lib and its tests only; (3) nothing else in L is droppable, because the seventeen settings fields and the eleven `Division` fields are free. Measure before the commit and record both numbers in the build log, as J and K did.
